# Complete rooted document-state storage

## Problem and example

A cold runtime cannot install independently decoded sessions into an otherwise empty document store. The next rooted operation also consumes exact lineage, occurrence, component, subscription, receipt, catch-up, publication and observed-result indexes. Reconstructing those families from current heads would discard historical and same-epoch authority. Eagerly opening every session would instead turn a selected-root restart into a catalog restore.

There is also a working-state issue: an existing rooted publication installs a copied session before attaching its final retained view. Writing a session or publication record at every intermediate map put would retain an incomplete row, or replace the actual mutable object before the operation is complete.

## Assembly and retained authority

`StoredDocumentStore` composes the qualified current row families into the actual complete `InMemoryDocumentStore.StoreState`. Its in-process `Selection` requires every named root plus all original generation, status-index and mutation-counter metadata. It is not serialized as a single root and is not a publication token. The host must select the roots from one coherent directory view and publish changed roots with the required read/absence/predicate fences. Family roots remain composable by owner/bucket; one realm-wide AVL root per family alone would not establish independent-writer publication.

Open authenticates bounded root metadata but never enumerates sessions or invokes replay, PROCESS, provider resolution, topology reconstruction or registration. Session addresses resolve lazily through one bounded owner. That owner memoizes the actual mutable selected session and shares one `DocumentSessionStorage.OpenScope` with publication records and the eventual engine factory's source/cohort restoration. Immutable original lineage, graph generation and rooted view remain separate from the working session's later status, READY or epoch changes.

Key-aware lazy projections put the existing selected cross-index checks below the original index APIs, including raw snapshot consumers. They check primary/reverse memberships, complete component proof against its original retained publication, subscription head/generations, numbered receipt identity and known-range holes, plan/barrier memberships, and original work/application associations. The minimum map validates the exact returned retained due key before normal selection can treat malformed derived storage as a semantic error. New working entries still follow the original registration/mutation algorithms; validation adds no logical comparisons, row counts, gas or selection steps.

An explicit bounded registry owns selected nested-map projections. It remembers exact family/key/root associations, not every document body. Unchanged subtrees retain their physical handles, copied unchanged values reuse encoded rows, and changed nested paths are staged back through their original bindings. A registry limit is a physical capacity failure, not a protocol budget. Selected absence checks do not turn a deliberate removal of an originally present working row into corruption. Topology readers enumerate membership keys without decoding values, so those complete selected buckets are checked when their outer value is selected; unrelated outer search-path values remain unopened.

## Compute, staging and publication

Rooted algorithms mutate their actual working StoreState. Immutable index path prewrites may occur, as in the component stores. Mutable sessions, typed publication rows and appended log suffixes remain working values until explicit `Opened.stage(completeState)`. Stage retains only complete current selected sessions, ignores removed/replaced original instances, and stages typed publication maps before new outbox/checkpoint chunks so every observed row retains its original processor-issued result association. It does not publish any returned root, replace the working tree, or reconstruct authority from final heads. A failed prewrite leaves the prior selection authoritative; retry uses the same actual working instances.

The owning engine/transaction must retain the `Opened` scope while it can access those rows and retire it afterward. The full engine factory must restore pending/source/feeder cohorts through `Opened.viewScope()`, not keep old Java view references or use a second interner.

## Scope and deliberate limitations

This component covers complete **document StoreState**, not a full fresh SDK or PostgreSQL application restart. Engine control, exact-object indexes, journal, routes, source discovery, captured cohorts and SDK metadata are separate selected families owned by the engine factory. The rooted atomic transition path preserves the lazy working maps. Legacy `insert/remove` still call the old resident `withSessions` rebuild and are not a qualified cold path; there is no hidden full-catalog fallback.

Selected session histories are still fully decoded within their record/scope limits. Explicit history and log enumeration remains exhaustive. Some selected membership checks inspect the complete relevant bucket. This is correctness and locality qualification, not a bounded total-history-memory or scaling claim. Independently valid but coherently forged unused rows cannot be detected by a point read; trusted pinned records and the host's coherent root selection remain prerequisites. Known selected crosslinks and receipt-range holes are checked rather than silently treated as absence.
