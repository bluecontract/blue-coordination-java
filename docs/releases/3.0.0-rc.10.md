## Decision

This named-Compute correction candidate is authorized for Maven Central
publication only after the exact Java 17 and Java 21 release gates complete
successfully. The markers declare the permitted release tier; they do not
record a completed build, passed test run, or published artifact. Readiness
must be established by fresh artifact-bound evidence for this candidate.

The public build must resolve this complete published tuple:

- Language and Contracts modules: `3.1.0-rc.25`;
- BEX core and contracts: `1.1.0-rc.6`;
- Repository: `3.0.0-rc.22`;
- Coordination: `3.0.0-rc.10`.

The dependency tuple, dependency locks, and generated POM are unchanged from
RC9. Coordination directly owns the complete Language graph and retains the
BEX and Repository transitive exclusions. Maven Local, sibling source
composites, invocation-owned development repositories, and staged repository
fallback cannot supply public release evidence.

## Changes since RC9

Compute definitions selected by name or document pointer execute during
initialization and later operations. Static-type validation resolves evidence
through the selected definition's exact working-document occurrence, including
a definition at the document root, instead of the selected workflow `steps`.
Unchanged inherited empty `constants`/`functions` declarations are excluded
from BEX input; execution and plan-cache identity retain the original frozen
definition. No public API is added and no protocol rule changes.

## Supported profile and required evidence

The candidate retains the bounded, sequential, single-JVM runtime release tier,
rooted checkpoint processing, drain accounting, and release-gate organization
of RC9. The complete current `releaseCheck` must pass on Java 17 and Java 21,
including unit, integration, built-JAR consumer and scenario tests, dependency
isolation, public API and publication checks, structural test architecture,
and an isolated build from the extracted source archive. Production bytecode
remains Java 17.

`verifyRcReadiness` retains the complete RC9 capability inventory. The release
workflow prepares one exact candidate and runs the full Java 17 staging gate
and Java 21 compatibility gate concurrently; publication waits for both
successful jobs and deploys only the verified Java 17 staged bytes after
comparison with the Java 21 built artifacts.

Only a successful current gate writes
`build/reports/release/3.0.0-rc.10-readiness.json` with freshly built artifact
hashes. Existing development exports and earlier RC receipts retain their
original meaning and do not certify this release.

## Explicit non-claims

- no authoritative Timeline-provider import or completeness contract;
- no Mandate or target-time eligibility implementation;
- no list-position identity for `Process Embedded.collectionPaths`;
- no import of arbitrary managed draft state through `ManagedDocumentDraft.atEpoch(...)`;
- no process-restart persistence supplied by Coordination itself;
- no distributed or multi-node durability, scheduling, or consensus;
- no production tenancy, authentication, operations, or stable latency SLA;
- no stable 3.0.0 API claim.

Applications must supply and verify their durable command, receipt, and
exact-content storage boundary. This candidate is intended for bounded
external pilots and local application integration.
