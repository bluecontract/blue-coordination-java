## Decision

This historical-representation candidate is authorized for Maven Central
publication only after the exact Java 17 and Java 21 release gates complete
successfully. The markers declare the permitted release tier; they do not
record a completed build, passed test run, or published artifact. Readiness
must be established by fresh artifact-bound evidence for this candidate.

The public build must resolve this complete published tuple:

- Language and Contracts modules: `3.1.0-rc.24`;
- BEX core and contracts: `1.1.0-rc.5`;
- Repository: `3.0.0-rc.22`;
- Coordination: `3.0.0-rc.6`.

Coordination directly owns the complete Language graph and retains the BEX
and Repository transitive exclusions. The generated POM, dependency locks,
and resolved runtime graph must agree before staging. Maven Local, sibling
source composites, invocation-owned development repositories, and staged
repository fallback cannot supply public release evidence.

## Supported profile and required evidence

The candidate retains the bounded, sequential, single-JVM profile of rc.5
and adds authenticated historical representation positions to managed
catch-up. Representation-only transitions must retain their exact anchor,
predecessor, cursor, and publication evidence without replaying source events.

The complete current `releaseCheck` must pass on Java 17 and Java 21. It
includes unit, integration, built-JAR consumer and scenario tests, dependency
isolation, public API and publication checks, structural test architecture,
and an isolated build from the extracted source archive. Production bytecode
remains Java 17.

`verifyRcReadiness` also requires the existing retained-epoch, cyclic-proof,
checkpoint-settlement, atomicity, response-loss, locality, nested-readiness,
same-state publication and reference-transparent test inventories, plus:

- `ManagedRepresentationHistoryTest`: authentication of intermediate and
  terminal history, rejection of forged anchors and predecessors, and
  agreement between processor proof and SDK traversal;
- `HistoricalRepresentationApplicationIntegrationTest`: saved-original
  reconnect, figure-eight formation, joined/split loops, and ring/chord
  reconnect with duplicate-occurrence and source-event preservation.

Only a successful current gate writes
`build/reports/release/3.0.0-rc.6-readiness.json` with freshly built artifact
hashes. Existing development exports and rc.4/rc.5 receipts retain their
original meaning and do not certify this release.

## Explicit non-claims

- no authoritative Timeline-provider import or completeness contract;
- no Mandate or target-time eligibility implementation;
- no list-position identity for `Process Embedded.collectionPaths`;
- no creation of a new authored nested lineage during retained catch-up;
- no process-restart persistence supplied by Coordination itself;
- no distributed or multi-node durability, scheduling, or consensus;
- no production tenancy, authentication, operations, or stable latency SLA;
- no stable 3.0.0 API claim.

Applications must supply and verify their durable command, receipt, and
exact-content storage boundary. This candidate is intended for bounded
external pilots and local application integration.
