## Decision

This release-orchestration follow-up candidate is authorized for
Maven Central publication only after the exact Java 17 and Java 21 release
gates complete successfully.
The markers declare the permitted release tier; they do not record a completed
build, passed test run, or published artifact. Readiness must be established by
fresh artifact-bound evidence for this candidate.

The public build must resolve this complete published tuple:

- Language and Contracts modules: `3.1.0-rc.25`;
- BEX core and contracts: `1.1.0-rc.6`;
- Repository: `3.0.0-rc.22`;
- Coordination: `3.0.0-rc.9`.

Language RC25 supplies the rooted processing context and publication projection
APIs used by this branch. The bundled SDK Contracts identities bind the rooted
release, including specification
`sha256:e91381c970859a6bafecdd99e46f5115ba033bf0534be84bbd5582531e9e347f`
and release
`sha256:156b58c6a19ab94cd3d1759dbbd115963c6d345c69511113798824cb5c749ced`.
BEX RC6 is the published BEX release verified against Language RC25.

Coordination directly owns the complete Language graph and retains the BEX
and Repository transitive exclusions. The generated POM, dependency locks,
and resolved runtime graph must agree before staging. Maven Local, sibling
source composites, invocation-owned development repositories, and staged
repository fallback cannot supply public release evidence.

## Supported profile and required evidence

The candidate retains the bounded, sequential, single-JVM runtime release tier
and rooted checkpoint processing of RC8. A selected root calculates required
forward dependencies while publication is restricted to verified owners.
Incoming observers do not enlarge a source invocation. Historical attachments
retain exact source positions, authenticated beginnings, and frozen logical
input boundaries. Source prerequisites and root-local history remain explicit
work; incomplete required history cannot advertise a newer ready state.

The complete current `releaseCheck` must pass on Java 17 and Java 21. It
includes unit, integration, built-JAR consumer and scenario tests, dependency
isolation, public API and publication checks, structural test architecture,
and an isolated build from the extracted source archive. Production bytecode
remains Java 17. Historical fixtures retain their original profile; their
rooted variants must execute against the current published dependencies.

`verifyRcReadiness` retains the complete RC8 capability inventory, including
the rooted admission-basis, publication-authority, source-isolation,
source-prerequisite, frozen-frontier, checkpoint-representation, declared-child,
cycle-entrypoint, gas-boundary, and local-history-recovery tests. These cover
exact owner fences, declared birth identity, source-independent scheduling,
retained history, shared gas limits, atomic publication, and retry behavior.

The RC8 drain accounting remains in place: every newly committed owned PROCESS
revision counts toward the drain transition budget. Unowned dependency
calculations and replayed publications remain excluded; each invocation remains
atomic.

The release workflow prepares one exact candidate and runs the full Java 17
staging gate and Java 21 compatibility gate concurrently on separate runners.
Publication waits for both successful jobs. Their handoffs bind the source
commit and tree, release version, workflow run, dependency lock, complete test
inventories, topology and extracted-source evidence, and built artifact hashes.
Only the verified Java 17 staged bytes are deployed after comparison with the
Java 21 built artifacts; publication does not repeat the completed test gates.

The RC8 test organization and optimizations remain in place. Every suite still
runs independent classes in four JVMs and retains its complete test inventory,
assertions, gas and restart matrices, all 32 topology scenarios, and repeatability
checks. The complete execution-scope gate rejects missing, skipped, or filtered
suites and an excluded or skipped topology comparison. Release-job concurrency
does not change the supported runtime profile.

Only a successful current gate writes
`build/reports/release/3.0.0-rc.9-readiness.json` with freshly built artifact
hashes. Existing development exports and earlier RC receipts retain their
original meaning and do not certify this release.

## Explicit non-claims

- no authoritative Timeline-provider import or completeness contract;
- no Mandate or target-time eligibility implementation;
- no list-position identity for `Process Embedded.collectionPaths`;
- no import of arbitrary managed draft state through `ManagedDocumentDraft.atEpoch(...)`;
- no process-restart persistence supplied by Coordination itself;
- no distributed or multi-node durability, scheduling, or consensus;
- no production tenancy, authentication, operations, or stable latency SLA;
- no stable 3.0.0 API claim.

Applications must supply and verify their durable command, receipt, and
exact-content storage boundary. This candidate is intended for bounded
external pilots and local application integration.
