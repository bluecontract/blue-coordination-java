## Changes from RC14

This candidate publishes general Timeline entry support merged in
[PR #31](https://github.com/bluecontract/blue-coordination-java/pull/31).
Original exact envelopes are retained; operation metadata is optional. Registered
channel semantics route general entries through ordinary managed processing,
source prerequisites and historical catch-up. Malformed or unsupported Operation
Requests reject without falling back to general delivery. Outer delegation
remains unsupported. Complete entry, graph and catch-up operations stay atomic.

Referenced Operation Requests now preserve document and exact-version selectors:
Coordination reads these fields from the verified materialized message in every
engine and rooted routing view. Missing evidence cannot become broadcast. No
lower-library version or workflow semantics change accompanies this correction.

Persisted entry-bearing formats change intentionally. Only the new formats are
supported; preceding formats reject explicitly. No backward adapter, legacy
migration or automatic data reset is provided. Hosts must arrange the breaking
cutover rather than continue processing old documents or entries.

The [combined report](https://github.com/bluecontract/myos-simple/blob/857fc426c5a7b365299612963c35b3c0079159d1/docs/general-timeline-entry-report.md)
records the unchanged reviewer20/20 reproducer, affected native proofs, bounded
Mini31PostgreSQL/32concurrency/1packagedHTTP cases and exact artifact identities.
PR CI passed1,830 cases. These are pre-publication results, not an RC15 release
receipt. The exact compound partial-coverage-at450 fixture remains unexecuted;
existing topology invalidation and separate stale-selection/availability controls
are documented. Broad Mini parity, stable API approval and historical storage
costs remain outside this qualification.

The published Language/BEX/Repository dependency tuple remains unchanged.
Fresh exact-source Java17 release verification is required before publication;
prior PR/local test receipts are not relabeled as RC15 release evidence.

## Release boundary

This external-state POC candidate may be published only after fresh, exact-source
Java 17 release gates pass. These markers declare the permitted tier,
not completed tests or publication. RC11's rooted processing rules remain the
baseline; this candidate extends managed entry admission and routing while preserving
event ordering, atomic operation boundaries, logical gas and failure policy.

## What this adds to RC11

- Complete external-state engine and SDK open/stage adapters. Named descriptors
  preserve document sessions, topology and occurrence state, pending selections,
  source prerequisites, feeder progress, SDK maps and publication evidence across
  fresh owners. Reopening is not reinitialization or input replay.
- Host-owned immutable object and Timeline journal ports, granular persistent
  indexes, receipt/result indirection and append-oriented session history. The
  library chooses exact retained representations; the host chooses storage,
  transactions, scheduling and cache capacity. No PostgreSQL or Redis dependency
  is added to Coordination.
- Bounded decoded-artifact and verified-frame reuse, including representation
  evidence and exact historical results. Cache reuse does not replace current
  membership, publication, predecessor or input-context checks. Foreign, missing,
  corrupt and incompatible records remain errors, not authority supplied by a
  host boolean.
- Indexed journal positions, application-result/READY revision lookup, selected
  view reuse and incremental publication support. These reduce repeated reads,
  reconstruction and host projection work without changing the selected logical
  action or dropping historical gas/evidence.
- Cold-open, restart, corruption, mutation, cache eviction and physical-failure
  controls. Failed processing scopes must be discarded; immutable staging alone
  never publishes a document transition.

## Host responsibilities and non-claims

The host must select coherent named state/journal versions, retain read and
absence fences, atomically publish successful updates and durable work evidence,
and discard stale or physically failed processing attempts. Object prewrites and
cache entries are not publication. SDK handles belong to their runtime owner.
Resident operation remains supported alongside the external-state adapters.

This release does not supply a database, distributed leases, worker scheduling,
notification fan-out, multi-node consensus, production tenancy or a latency SLA.
It does not claim constant memory/time for arbitrary history length or fully
preemptible processing within one frozen call. Large-history scalability and
host fairness remain measured follow-up work, not a semantic shortcut.

RC11's other explicit exclusions remain: no authoritative Timeline-provider
import/completeness service, Mandate/target-time eligibility, list-position
identity for embedded collections, arbitrary managed-draft import, or stable
3.0.0 API claim. The C03 nested/contextual identity family remains deferred.

## Required qualification

The complete `releaseCheck` must pass on Java 17: all discovered
unit, integration, built-JAR consumer and scenario tests; topology and execution
scope receipts; dependency isolation; public/SDK boundaries; documentation;
publication metadata; and an isolated build from the extracted source archive.
Production bytecode remains Java 17. No filtered POC suite substitutes for this.

`verifyRcReadiness` preserves the earlier capability inventory and checks the
exact RC15 tuple and tier. Only a successful current gate writes
`build/reports/release/3.0.0-rc.15-readiness.json` with artifact hashes.
The release workflow requires all three test groups and the extracted-source
check, validates their exact-source receipts, and runs the remaining complete
release gates before sealing and publishing Java 17 artifacts. MyOS resident/PostgreSQL acceptance against these published
artifacts follows publication and is recorded separately; earlier development
receipts are not relabeled as this release's acceptance.
