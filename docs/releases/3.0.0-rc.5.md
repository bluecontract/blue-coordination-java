## Decision

This candidate is authorized for publication to Maven Central after the exact
Java 17 and Java 21 release gates complete successfully. It is intended for
bounded external pilots and local application integration. It is not a stable
or production-ready release.

The public build resolves only published artifacts. Maven Local, sibling
source composites, invocation-owned development repositories, and remote
fallback from a staged repository are excluded from release evidence.

| Component | Version |
| --- | --- |
| Language and Contracts modules | `3.1.0-rc.23` |
| BEX core and contracts | `1.1.0-rc.4` |
| Repository | `3.0.0-rc.21` |
| Coordination | `3.0.0-rc.5` |

Repository rc.21 and BEX rc.4 advertise older transitive Language edges.
Coordination excludes those edges, directly owns the complete rc.23 Language
graph, and verifies the generated POM, dependency lock, and resolved runtime
graph before staging.

## Supported profile

- automatic managed-occurrence resolution for exact current, authored-initial,
  initialized epoch-zero, and uniquely retained managed states;
- complete duplicate-preserving managed-epoch receipts, occurrence-specific
  catch-up plans and cursors, transitive readiness barriers, and restart-safe
  response-loss reconciliation;
- retained catch-up through ordinary acyclic and bounded cyclic processing
  without reinitializing or source-processing the retained lineage;
- deterministic provider-backed invocation bodies for current and historical
  retained values, including eventless epochs whose BlueId is unchanged;
- verified checkpoint settlement before representation-only rebind, with
  atomic publication and rollback on malformed or stale evidence;
- immutable proof-aware exact-node resolution for cyclic member identities,
  with distinct missing-content, missing-proof, and invalid-proof outcomes;
- lazy reference-transparent SDK execution for ordinary pure references,
  including exact demand/resume, locality, and copy-on-write patch semantics;
- host-driven bounded processing slices and read-only availability hints while
  preserving deterministic single-JVM processing order; and
- Java 17 bytecode with complete Java 17 and Java 21 verification.

## Release evidence

`verifyRcReadiness` depends on the complete current `releaseCheck`, dependency
preflight, built artifacts, source-archive extraction, structural test
architecture, consumer tests, integration tests, and scenario tests. It also
requires the focused retained-epoch, cyclic-proof, checkpoint-settlement,
atomicity, response-loss, locality, nested-readiness, same-state publication,
and reference-transparent test inventories before writing
`build/reports/release/3.0.0-rc.5-readiness.json`.

The historical rc.4 dynamic-evolution handoff remains retained evidence for
that release only. It is not used to authorize rc.5 and its earlier capability
limitations are not reinterpreted.

## Explicit non-claims

- no authoritative Timeline-provider import or completeness contract;
- no Mandate or target-time eligibility implementation;
- no list-position identity for `Process Embedded.collectionPaths`;
- no creation of a genuinely new authored nested lineage during retained
  catch-up;
- no process-restart persistence supplied by Coordination itself;
- no distributed or multi-node durability, scheduling, or consensus;
- no production tenancy, authentication, operations, or stable latency SLA;
- no stable 3.0.0 API claim.

The runtime remains one JVM, in-memory, and sequential. Applications that need
durable command, receipt, or exact-content storage must provide and verify that
host boundary explicitly.
