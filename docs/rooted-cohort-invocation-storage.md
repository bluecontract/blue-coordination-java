# Exact captured cohorts, not runtime recapture

## Problem and example

A parent stopped for source history retains more than a Language input. Its
cohort also fixes captured host heads, per-document graph generations, layouts,
routes, next application orders, a declared draft plan, prior automatic
expansions, publication identity lanes, original rooted histories, selected
historical views and physical publication fences.

For example, a declared child birth can suspend, authenticate its actual emitted
demand and expand the input. That expanded cohort retains the original entry
owner context and the consumed demand's original marker. Re-reading current
heads, rebuilding layouts, stamping that demand with the expanded input's ID or
executing the parent to rediscover it would change the captured evidence.

## Minimal storage boundary

`CohortInvocationStorageCodec` retains a closed complete cohort record. Its
associated attempt operation additionally stores the actual Language attempt,
input and optional retry. Decode checks their byte-exact association and returns
the selected demand from the restored attempt's actual ordered list.

Language owns original input/retry/cause/demand transport, including private
rooted bindings and emitted demand markers. Coordination uses those typed
operations and does not duplicate their field mappings or expose an authority
constructor. The cohort's rooted record is checked against
`originalRootedBinding(input)`; its original context is never derived from an
expanded graph. Captured document and publication fences remain operational
data, not authority inferred from a current store.

The existing operation-plan codec owns declared draft fields. Session row
helpers are reused for exact values, embedded layouts, subscriptions and rooted
admission histories. Extracting the two reusable session row helpers leaves the
existing session wire format unchanged.

`ManagedWorkStorageCodec` is the reusable complete historical work row mapping.
It preserves the ordinary, representation and numbered-with-future-successor
domains separately, restores both cause roles through Language, invokes the
existing exact domain constructors and compares the original work identity.
It rejects two incompatible cause roles, an incorrect type, a changed cause
domain or coordinates that do not reconstruct the asserted identity.

## View identity and physical limits

Views remain separately addressed immutable objects. `DocumentSessionStorage`
adds package-only retention and read access to its existing bounded `OpenScope`.
Sessions and cohort history/origin references therefore use the same immutable
view instances regardless of open order. There is no second view interner,
global mutable runtime root or whole-runtime snapshot. Closed scopes reject
further lookups; named view reads retain existing byte, digest and scope bounds.

Cohort records use the existing bounded physical framing and canonical
re-encoding. The enclosing immutable object/index record is responsible for the
authenticated selected address and publication. Immutable view prewrites alone
do not publish a cohort or change any semantic state. Decode has no provider,
journal, current document store or PROCESS port.

The outer declared-birth rejection packet has an additional preexisting alias
constraint: selected and executed cohorts refer to the same draft-plan object.
That packet must retain one shared exact plan reference when it restores both
cohorts; independently decoding equal plans is not a replacement for that guard.
The source coordinator's pending/submitted/completed maps are a separate slice.

## Focused controls and limits of the claim

The focused owner uses actual SDK captures and processor-issued demands. It
checks declared birth suspension, expanded consumed demands, a bare source
prerequisite, a prepared saved-C0 retry while C1 is already selected elsewhere,
cold full-result/gas parity after producer close, untouched source
and parent histories, exact local historical origin/work, and selected view
identity shared with restored sessions. Missing or corrupt selected views fail
closed while unrelated corrupt objects remain unread. Malformed framing,
operational bounds, absent original ownership and mutable returned copies are
negative controls.

The fresh processor still needs the independently retained accepted Timeline
request body for subsequent execution. The cold control first leaves that exact
resource unavailable and proves an ordinary `EXACT_NODE` suspension for its
actual request BlueId. It then supplies the original fixture's exact-object
bytes and proves full-result/gas parity. Cohort decode occurs before either
PROCESS call, with zero provider reads; it neither acquires that request nor
claims to restore the separate object-store or journal lane.

Standalone work controls use a genuine same-epoch processor transition with
explicit test work coordinates; they do not claim those test coordinates were
scheduled by a source coordinator. Ordinary, representation and future-successor
work remain different exact domains after restore. This component gate does not
claim complete engine/SDK cold-start recovery or pending-map installation.
