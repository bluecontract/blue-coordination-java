# Verified managed-history artifacts

## Problem

The physical receipt codec already caches fully verified immutable receipts across fresh runtime owners. The ordinary SDK audit nevertheless creates new public wrappers on every call; host projection then re-encodes and independently proves all old source bodies. For a retained prefix of N receipts and one append, that repeats expensive work on N unchanged values. A receipt identity alone is insufficient to authorize reuse of another wire representation or cyclic proof.

## Library-issued history and content

`AdvancedCoordination.auditManagedEpochHistory(documentId, previous)` first performs the ordinary current engine history read. It then compares the exact retained low-level receipt objects, their positions, source lineage, and complete SDK storage configuration. Only the unchanged leading objects borrow prior SDK snapshots and encoded content. The new suffix alone is projected/encoded; a cold call, changed object, different document/configuration or shorter history cannot borrow the old prefix. The existing canonical per-receipt cache supplies identity across independently opened owners. This is not another global cache.

`ExactBlueValue.verifiedEvidence()` returns a final, non-publicly-constructible `VerifiedExactEvidence`: exact BlueId, the same JSON as the ordinary SDK serializer, and the complete ordered cyclic placeholder proof when present. It is issued from the already authenticated immutable ExactValue, not from arbitrary `ExactNodeEvidence`, strings, or a trust boolean. Hosts may use it to avoid immediately re-proving content produced or restored by the library, but must bind their candidate body/proof to this artifact and separately establish current source/first-provenance authority. New rows may still need host-specific canonical key sorting once.

The private managed-receipt index codec also preserves the producer receipt object after its complete raw decode and exact re-encode accept the newly written frame. This moves the existing first cold canonical verification to insertion; it does not skip that verification or certify arbitrary public objects. The following map roundtrip reuses the finished proof. Later owners can therefore recover the same immutable producer receipt and extend the prefix across actual publish/reopen cycles, not merely reopen one unchanged selection. Disabled/oversized/evicted caches use the ordinary decoder.

History artifacts deliberately detach Timeline metadata from live SDK handles. Caching ordinary receipt wrappers would retain a TimelineHandle's BlueCoordination owner and therefore its entire runtime; the new history cannot keep an engine, mutable session, provider, meter, or command authority alive. Detached handles are not accepted by any execution environment. Gas, receipt fields, event occurrence order and equal-event duplicates are unchanged.

## Persistence, budgets, and limits

The host must bound history retention. `estimatedRetainedBytes()` charges newly retained body/proof/event/source-entry text with an eightfold graph allowance and charges shared graphs repeatedly; this is an estimator, not a measured JVM heap bound. Prefix weights and exact content artifacts are reused without visiting their graphs again. Hosts must partition an existing budget rather than treating this capability as free memory.

The token is not serialized authority. A cold process still verifies stored library frames once through the normal codecs; eviction/new receipt objects produce a cold suffix. Stored fingerprints or a high-water mark do not authorize missing, replaced, or corrupt SQL rows. The host's fresh bounded prefix row checks remain necessary and O(history); only old serialization/mathematical proof work is removed. Physical revision-record deltas are a separate session-storage responsibility. No claim is made that all history reads, metadata copies, or cold verification become O(delta).

Controls cover 5/50/100-row cold/warm/+1 projection counts, exact object/artifact reuse, foreign configuration/document and reconstructed-equal fallback, later malformed history, duplicate events/gas, detached handles, actual fresh storage owners with process cache and eviction, physical failure, and mutable-copy/proof tampering. The coordinated native qualification closed on 2026-09-16: 105 invocations across 13 complete owners passed cumulatively (98 from controls02 plus all seven rooted-storage cases from controls03 after correcting only the test's session-format detector). The initial compile failure and detector failure remain archived. Javadoc, exact production shape and both API boundaries passed. These controls establish the stated local correctness and reuse counts, not an end-to-end performance benefit or full host acceptance.
