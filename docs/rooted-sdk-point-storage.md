# Selected rooted SDK metadata rows

## Problem and exact boundary

The SDK's Timeline, submission intent, retained entry result, verified core-entry reference and source-prerequisite result maps are point-accessed during normal execution. The earlier complete `SdkStorageCodec.Metadata` transport proves lossless values and owner rebinding, but decoding that complete map image for every selected owner would load unrelated entries and couple independent writers if treated as one publication root.

For example, reading the retained outcome of one targeted `setCounter` needs that result and its registered Timeline. It does not need every other result or even that submission's intent/core row until the intent is selected. A missing referenced core row must nevertheless fail when the intent is read; it cannot become the SDK's ordinary broadcast default.

## Closed row component

Package-private `SdkPointStorage` reuses the current `SdkStorageCodec` for five closed kinds. It stores immutable SHA-256-addressed bytes through `CoordinationImmutableObjectStore`. Each row and its opaque descriptor independently bind the version, kind, complete actual configuration and complete key. Source-result keys include every field of `SourceHistoryPrerequisite`, not only its claimed selection identity. The complete configuration includes language/Contracts identities, policy, content-derived identity mode, release mode and bundled identities; it is not inferred from an environment variable or substituted by a partial policy label.

`retain*` only retains an object and returns descriptor bytes. It does not publish an index or accept a root. Descriptor adoption is a bounded defensive copy. The caller must select descriptor membership from authenticated indexes and retain their point/predicate reads in the publication read set. The `References` callbacks explicitly select required Timeline/core-entry descriptors from that same pinned runtime. This component adds no global map root, CAS, enumeration or publication authorization.

A scope is opened through the actual owning SDK runtime, which supplies its owner, actual configuration and actual engine binding. Selected reads rebind SDK handles to that owner and verify the registered Timeline's actor/kind. Core rows are compared with the engine's verified journal row, including exact event/request, orders and all append coordinates; the returned `TimelineEntry` comes from that verified journal, never a plain reconstruction constructor. Targeted intents must match the original journal's exact document reference, operation, channel, Timeline and actor. The original target-presence/lineage selection fields remain retained historical metadata, not a reinterpretation of the current head. Entry and source results validate each referenced handle's journal coordinates. Results need not be SDK submissions, so they do not require universal membership in the SDK core-entry map; an intent does require its exact core descriptor and bytes.

All selected physical failures remain noncommitting, preserving an existing `NoncommittingExecutionException` unchanged. There is no replay, provider resolution, append, admission, PROCESS, implicit parent continuation or mutation of live SDK maps in these reads.

## Bounds, ownership and lifetime

Operational limits bound descriptor bytes, complete row bytes and per-scope memo charge/entry count. Descriptor/declared row limits are checked before an object read. The host receives the exact declared row byte cap; returned length, digest, canonical framing and complete row binding are checked. A row too large for the memo is still readable within the row bound but is not retained. Zero memo capacity disables retention. These are physical limits, not new semantic cardinality or gas limits.

The access-ordered memo charges encoded row plus descriptor bytes and caps entry count. This is an explicit encoded-size accounting bound, **not** an exact JVM heap measurement. Independent simultaneously live scopes multiply the configured budget. Decoded objects and their owner-bound handles never cross scopes. Reads and close are synchronized; closing clears the memo. Reads also reject a closed SDK owner. The selected-runtime caller must close its scope, including failed attempts; no complete backing-resource lifecycle has been installed in the SDK yet.

Memo hits reuse previously authenticated immutable bytes/typed values and still check selected journal/Timeline bindings. A memo is not continuous corruption scrubbing: illegal deletion/corruption of an already captured object is observed on a fresh scope or an eviction miss, not by discarding previously verified immutable values. Missing selected dependencies never receive an empty/default replacement.
